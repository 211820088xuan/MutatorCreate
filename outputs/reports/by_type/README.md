## 三种分析方法（互相独立，失效方式各不相同）

| | 方法 | 做什么 | 回答的问题 |
|---|---|---|---|
| **一** | 动态污点追踪 | 把漏洞版本的程序**真实运行**，给函数参数做记号并逐指令跟踪 | 出错的那个量**是不是由某个参数算出来的** |
| **二** | 静态数据流分析 | **不运行**，只读源码构建代码结构图 | **有没有一条通路**从参数通到出错行 |
| **三** | 修复补丁分析 | 取官方**真正的修复提交**，归类其改动 | 人类开发者认为**根因是什么、补了什么检查** |

三种方法的数据来源与原理完全不同。**同时成立时证据最强**；只有一种支持时只能算线索。

## 两点方法论说明

**1. 所有数字都从原始分析结果现算，未手工填写。**
本轮曾发生文档数字与数据漂移的情况，已逐条对账修正。

**2. 报告刻意区分"证据强度"。**
每份报告都标注了样本量与跨项目范围，并对以下情形明确降级处理：
* 结论仅来自单一项目 → 标注为"不可外推"
* 多条崩溃同源（同一出错点） → 标注独立样本量
* 关键比例建立在个位数样本上 → 标注"不具统计意义，只作方向参考"
