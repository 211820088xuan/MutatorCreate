## 1B 的关键验证：DWG 没有从 DXF 变异长回来

`reps_n5_dxfonly/rep01` 语料按首两字节分类：

| 臂 | 条目数 | DXF | DWG | JSON |
|---|---|---|---|---|
| default | 741 | **740 (99.9%)** | 1 (0.1%) | 0 |
| custom | 565 | **564 (99.8%)** | 1 (0.2%) | 0 |

**DWG 占比 0.1–0.2%，远低于 10% 的门槛** → 路径 C（DXF-only 语料）的**前提成立**。

**已查清**：那 1 个"DW"DWG 条目**不是种子副本**。逐个取出其首字节与 sha1：

| 臂 | 文件名(sha1) | 大小 | 前 16 字节 |
|---|---|---|---|
| default | `dc6bf7340940…` | 4,533 | `b'AC10 ASSOCECTION'` |
| custom | `f861306712fd…` | 49,731 | `b'AC2.0\r\nSECTION\r\n'` |

两者都不是 `Arc.dwg`（sha1 `24ea2351a337…`）或 `Constraints.dwg`（sha1 `0bf261176851…`）。
它们是 **DXF 派生的输入，首两字节被变异成了 `AC`**，于是按 harness 的
`Data[0]=='A' && Data[1]=='C'` 规则被路由到 `dwg_decode`。

所以 1B 的"DXF-only"语料里那 0.1% 的"DWG"是**变异副产物，不是种子泄漏**——
路径 C 的前提成立：**把两个 `.dwg` 种子移走后，DWG 语料确实没有从种子长回来**。

## 失败与存疑

1. **1B 与预期方向相反**：指令里的硬停止点写的是"若 1B 的 RR 显著 > 1（CI 下界 > 1）"，但实测是
   **RR = 0.441、CI 上界 0.69 < 1**，即 custom **显著更差**。按指令记录并继续。
2. **1A 的绝对值不可比**：复跑的 default execs 是 42,912，旧的是 51,967（-17%）；
   在同一硬件、同一 150 s、同一并发度下，exec 总量差了近两成，未查清原因
   （怀疑是主机负载 / 页缓存状态不同）。所以**只比每 100k 的率，不比绝对 exec 数**。
3. **1A 与旧值的符号翻转**：RR 从 0.954（CI 含 1）变成 1.131（CI 含 1）。
   两次都不显著，但两次的**点估计方向相反**——这本身说明该配置下效应量在噪声以下。
4. **1B 的 default 密度反而更高**（26.52 vs 1A 的 95.54？不，1B 更低）。1B 的 default 是 26.52/100k，
   1A 是 95.54/100k —— 去掉 DWG 后 default 的**目标密度降到 28%**。原因是每 rep 的 execs 从 6,900–10,600
   涨到 83,000–87,900（DXF-only 语料更小更快），分母变大 8–10 倍，分子只涨 1.5–5 倍。
5. ~~那 1 个来源不明的 DWG 条目~~ → **已查清**：是 DXF 变异后首两字节变成 `AC` 的副产物，非种子泄漏。

## 下一阶段的前提是否成立

**成立，但方向被 1B 修正了。**

- 1B 证明：**单纯去掉 DWG 种子不会让 a001 变好，反而显著变差**（RR 0.441，0/5 配对胜出）。
  原因从 Phase 3 的视角看很直接：DXF-only 语料里目标结构（`OBJECTS` 段）**仍然存在**，
  所以 a001 还在做"替换"；而 default 在同样的小语料上跑得快得多（426k vs 196k execs），
  用更多次数弥补了效率。→ **路径 C 作为"放大效应量"的手段是失败的**。
- 但它**没有否定 Phase 3**：Phase 3 要解决的是"结构不存在时 a001 空转"，
  而 1A/1B 的语料里结构都存在。Phase 3.5 用的是**剥段种子**（结构不存在），
  那是另一个场景，见 `PHASE3_REPORT.md`。
