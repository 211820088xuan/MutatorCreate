# V2 对照实验

同一二进制，`LIBREDWG_MUTATOR_OFF` 切换（`=1` → 100% default；`=0` → V2 算子）。
180 s × 2 臂。种子：6 个 DXF + 2 个 DWG（`Arc.dwg`、`Constraints.dwg`）。

## 现在的配置：**default 50% + 唯一的 found 特征 50%**

`s5f_feature_pipeline.py` 对 5 个 UAF 特征跑同一套 6 阶段流程，结果：

| 特征 | 状态 | 站点 | 权重 |
|---|---|---|---|
| uaf-llm01 同函数释放后访问 | ✅ found | `src/in_dxf.c:12284 → 12267` | **0.50** |
| uaf-llm02 缓冲区释放后旧指针 | ❌ not_found | — | 0 |
| uaf-llm03 清理析构后悬垂访问 | ❌ not_found | — | 0 |
| uaf-llm04 跨函数陈旧对象访问 | ❌ not_found | — | 0 |
| uaf-llm05 容器节点销毁后遍历 | ❌ not_found | — | 0 |

## 结果

| 口径 | default | custom | 比值 |
|---|---|---|---|
| execs | 13,049 | 6,533 | 50.1% |
| exec/s | 82 | 45 | 55% |
| cov | 24,128 | 24,098 | **99.9%** |
| ft | 44,000 | 38,621 | 87.8% |
| corpus | 786 | 352 | 44.8% |
| 崩溃文件 | 21 | 12 | — |
| 唯一崩溃点 | **2** | **1** | — |
| **目标触发密度** | 137.94 / 100k | **183.68 / 100k** | **1.33×** |

**目标触发率比 RR = 1.332，95% CI = **[0.64, 2.76]**，含 1 → 单次运行不显著。**

## 三种配置对比

| 配置 | exec/s | cov 相对 default | corpus | 目标密度相对 default |
|---|---|---|---|---|
| 100% a001（无 default） | 2.2% | 89.1% | 9 | 1.52× |
| 50% + 5×10%（4 个 generic） | 131% | 85.3% | 605 | 0.60× |
| **50% + 1×50%（只留 found）** | **55%** | **99.9%** | 352 | **1.33×** |

**"只保留找到落点的特征"明显好于"5 个都塞进去"**：覆盖率从 85.3% 回到 99.9%，
因为不再有 4 个哑弹占用 40% 的预算。

## 一个新发现

default 臂在加了 DWG 种子之后，多出一个**新的唯一崩溃点**：

```
SEGV @ in_dxf.c:971  × 3
```

custom 臂没有命中它（因为 50% 预算固定在 a001 上，执行量也只有一半）。
这是把 DWG 种子加进来之后才暴露的，值得单独跟进。

## 局限

1. **n=1**（每个臂只跑一次），基线自身波动可达 1.7–3 倍，所以 1.33× 不显著。
2. custom 的执行量只有一半（6,533 vs 13,049）→ 唯一崩溃点少一个（1 vs 2）。
3. `not_found` 的 4 个特征里，**llm04/llm05 是方法局限**（行级扫描器建立不了跨函数关系），
   不等于"不存在"；llm02/llm03 是查证过的（8 处 realloc 全部回写同一变量、清理路径无真实释放后读）。

## 下一步

1. **重复实验 ≥5 次**，配对检验，给置信区间。
2. **补第 ⑦ 步（跨函数关系）**，把 llm04/llm05 从"方法局限"变成"可判定"。
3. 跟进 `in_dxf.c:971` 这个新 SEGV。
