## 【一】过滤器按崩溃类型配（不再写死 UAF）

### 查表架构（`tools/r26b_scan.py::CRASH_FILTERS`）

| 类型 | 描述 | 触发正则 |
|---|---|---|
| **uaf** | 释放后使用 / double free | `\b\w*(?:free\|Free\|FREE)\w*\s*\(` / `\bdelete\b` / `\brealloc\s*\(` |
| **hbo** | 堆缓冲区溢出 | `memcpy\|memmove\|strcpy\|strncpy\|strcat\|sprintf\|snprintf\|alloca` / 数组下标 / 指针算术 |
| **stack** | 栈溢出 / 深递归 | `alloca` / 大局部数组（`[NNN]`，≥3 位）/ 函数定义（递归候选） |
| **global** | 全局缓冲区越界 | 全局数组声明 |

**同一组正则**同时用于：① **预过滤**（函数里没有任何触发点 → 不送 agent）；② **核对层**（触发行必须真有该类型的调用）。
`--type` 可以切，**换类型不用改代码**。

### 按 uaf 过滤器，四个项目能滤掉多少

| 项目 | worklist | 含释放调用 | **滤掉** |
|---|---:|---:|---:|
| **libredwg** | 162 | **44** | **116（72%）** |
| **leptonica** | 665 | **110** | **555（83%）** |
| libxml2 | 246 | 89 | 157（64%） |
| igraph | 40 | 2 | 38（95%） |

**leptonica 滤掉 83%** —— 这是步骤 2 成本的关键：665 个函数实际只需跑 **110 个**。

## 【二】token 开销：先查清楚，再砍

### 诊断（不是估，是读日志）

`docs/runs/r26/a/log_b*.jsonl`（办法 A 的最后一批）：

```
  事件计数: {'read_file': 25, 'grep': 26}
  每个 run 的日志条目: min=19 median=35 max=35
```

**一批只含 1 个函数，agent 却跑了 35 轮、调了 51 次工具**：

| 问题 | 实测 |
|---|---|
| 工具循环调了几次 | **read_file 25 次 + grep 26 次** |
| 每次重发多少历史 | **整个 messages 数组**（`Agent.run` 每轮 `self._chat(messages)`）→ 平方级 |
| 源码被读了几遍 | **整文件大段**：`read_file(path, 1700, 2078)` = **379 行**，而 prompt 里**已经有函数体** |
| 喂进去的是函数体还是整个文件 | prompt 是函数体 ✓，但工具又去读**整个文件** ✗ |
| 输出里解释性文字的占比 | 办法 A 没约束 → 大量 prose |

### 数量级对不上

```
  libredwg 162 个函数体合计      418,723 chars
  办法 A 的总 spent_chars     18,889,553 chars   ← **45 倍**
```

## 砍的四刀

| # | 改了什么 |
|---|---|
| **1** | **去掉 agent 工具循环，改单次 LLM 调用** —— 源码已在 prompt 里，不需要 read_file/grep；没有历史累积 |
| **2** | **只喂函数体**（`f["lines"]` 界定的那一段 + 行号），不喂整文件 |
| **3** | **输出纯 JSON 数组** —— system prompt 明确"只输出 JSON 数组，不要任何解释文字"；解析时兼容 ```json 包裹 |
| **4** | **预过滤** —— 按【一】的查表，函数里没有触发点就不送 |

### 每步的 chars / 耗时（都是实测）

| 方案 | 调用次数 | 输入 chars | 输出 chars | 耗时 |
|---|---:|---:|---:|---:|
| **A 基线**（工具循环，6→1 函数/批） | 324 | **18,889,553** | — | **142.5 min** |
| **1+2+3**（单次调用，无预过滤） | 320 | **874,922** | 28,937 | **5.1 min** |
| **1+2+3+4**（单次调用 + 预过滤） | **88** | **502,298** | 26,455 | **2.3 min** |

**输入 chars 降 37 倍、耗时降 62 倍、调用次数降 3.7 倍。**

### 为什么没出来（不是"看不见"，是"填错字段"）

`dxf_objects_read` 在预过滤后**是保留的** ✓（两个实例都跑了 ✓）。它报了 3 条（r1）：

```json
{"free_line":12284, "use_line":12287, "confidence":"high",
 "why":"第12284行在else分支释放pair后没有把pair置空或重新赋值，
        循环回到第12267行继续用pair->code判断，并在第12287行再次释放同一个pair，
        属于释放后使用和double free"}
```

**`why` 里明确写了「循环回到第 12267 行」** ✅ —— 但结构化的 `use_line` 填的是 **12287**（下一处 free）✗。

**端点统计**：

```
  free_line=12284: 实例 [1, 2]     ← 两个实例都报了 ✅
  use_line =12267: 实例 无         ← 一个都没填进字段 ❌
```

### 我试过的一个零成本补救（失败）

从 `why` 里抽行号补进使用点：**134 条候选里只有 1 条的 `why` 提到 12267**（r1）。
→ 补进去也只能是 **medium**（1 个实例），**不是 high** ✗。

### 按你的规则：**停下来报告**

**标尺不止掉到 medium，是根本没配出来。** 而且原因**不是知识缺失**，是**字段填写**：
