## 【一】过滤器按崩溃类型配（不再写死 UAF）

### 查表架构（`tools/r26b_scan.py::CRASH_FILTERS`）

| 类型 | 描述 | 触发正则 |
|---|---|---|
| **uaf** | 释放后使用 / double free | `\b\w*(?:free\|Free\|FREE)\w*\s*\(` / `\bdelete\b` / `\brealloc\s*\(` |
| **hbo** | 堆缓冲区溢出 | `memcpy\|memmove\|strcpy\|strncpy\|strcat\|sprintf\|snprintf\|alloca` / 数组下标 / 指针算术 |
| **stack** | 栈溢出 / 深递归 | `alloca` / 大局部数组（`[NNN]`，≥3 位）/ 函数定义（递归候选） |
| **global** | 全局缓冲区越界 | 全局数组声明 |

**同一组正则**同时用于：① **预过滤**（函数里没有任何触发点 → 不送 agent）；② **核对层**（触发行必须真有该类型的调用）。
`--type` 可以切，**换类型不用改代码**。

### 我的判断

**这条路（agent 圈 use_lines）在 UAF 上目前不可用。** 理由：

1. **标尺那条能对**（ASan 实测），说明**机制**通了；
2. **但 10/10 抽样全假** —— 说明它**大部分时候在报噪音**；
3. **噪音的来源是 `use_lines` 的语义质量**，不是配对逻辑（配对逻辑已经修了 5 个 bug）。

**三个选择**（我不替你定）：

| 选项 | 内容 |
|---|---|
| **(A) 收口** | 接受"agent 扫描在 UAF 上不可用"，写进限制；静态线回到 R22 的结论（只有 libredwg 一种形态能落地） |
| **(B) 只保留 `same_object` 那一类（39/41/44/13 里的 17/11/8/4）** | 丢掉 alias 和第三类，只留"使用行真的写了这个 object"的 —— **但刚核的 10 条里就有 6 条是 same_object** ✗ |
| **(C) 换判据**：要求 agent **同时给出 `use_code`（使用行原文）**，程序逐字核对它确实读了 object | 现在只有行号，程序只能看那一行有没有字符串 —— 给原文能挡掉"取地址""释放父结构体"这类 |

**我倾向 (C) 或 (A)** —— (C) 改动小，而且直接针对"程序看不到语义"这个根因。
