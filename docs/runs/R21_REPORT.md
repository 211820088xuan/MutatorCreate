**扫描范围仍然只有 worklist** —— 只扩"能读到的源码"。

### 顺带发现一个**范畴错误**（比步骤 1 本身更重要）

修好解析后我发现：`free(x)` / `LEPT_FREE(x)` / `xmlFree(x)` 这些**本身就是释放**，
但它们也被当成"包装函数"塞进了守卫 1 —— **查不到源码 → 拒绝 → 所有直接释放的站点被丢掉**。

窄条件修法：**只有当被调函数不在项目里、且名字像 free 原语时**才跳过守卫 1
（项目里的 `dwg_free_header_vars` 照旧走守卫 1，不会被跳过）。

**效果**：libredwg 原语 2→3、**leptonica 原语 0→1**（解锁！）。**新增的两条见步骤 2 的核实。**

## 步骤 2b · if/else 互斥守卫（用户决定 1）

### 做法

`pipeline/s5_6_lib.py::blocks()` 已经能算块边界（`kind ∈ loop/if/else/switch/plain`）——
这是**现成能力**的直接应用，只做最简单的一条：**释放和使用分属同一对 if/else 的两个分支** → 挡掉。

### 🔴 但一用就发现 `blocks()` 本身有两个真 bug

| # | bug | 证据 | 影响 |
|---|---|---|---|
| 1 | **假设 Allman 风格**（`{` 独占一行），永远看**上一行**当头部 | leptonica `pix4.c:3050` 是 K&R 的 `if (array) {` → 整块被标成 **`plain`** | **所有 K&R 项目的 CFG 都是错的** —— 不只是守卫失效，`flow()` / `loop_back` 也全错 |
| 2 | **`} else {` 这种写法判不出来** | `pix4.c:3056` = `} else {  /* L_SCAN_VERTICAL */`，`head` 是 `} else` → 不匹配 `^else` | else 块丢失 |

**两个都修了**（`blocks()` 改动两处：先看 `{` 所在行自己有没有头部代码；`hs` 先 `lstrip("}")`）。

### 守卫本身

```python
if use is same:                       # ← 只看最终采用的那个 use
    if exclusive_if_else(blocks(...), i, use_line - 1):
        continue
```
`exclusive_if_else` 检查**所有**外层 if/else 块（不只最内层 —— 使用点可能在 else 里嵌套的 if 中），
要求是**同一对**（else 的 header 紧跟在 if 的 `}` 之后，中间允许 `}`/空行/注释）。

### 效果

| 项目 | 加守卫前 | **加守卫后** |
|---|---:|---:|
| **libredwg** | 2 | **2**（不变，目标 `12284→12267` 仍是 `loop_back` ✅） |
| leptonica | 1（`3053→3064`，if/else 假阳性） | **1**（`3065→3064`，见下） |

**leptonica 的 `3053→3064` 被挡掉了** ✅ —— 但 `blocks()` 修好后 `loop_back` 通了，
冒出了 **6 个新的 `loop_back` 站点**。

### 🔴 又查出 `loop_back` 的一个真 bug（并修了）

`loop_back` 的"重赋值检查"原来只覆盖 **free → 回边**，**没覆盖下一轮从循环头到使用点**的重新赋值。

**证据**：leptonica `maze.c:459→403` ——
```
401:    while (lqueueGetCount(lq) > 0) {
402:        elp = (MAZEEL *)lqueueRemove(lq);   ← **下一轮在这里重新赋值**
403:        x = elp->x;                          ← 使用
...
459:        LEPT_FREE(elp);                      ← 释放
```
**修完后 6 个新站点里 5 个被挡掉**，只剩 1 个。

### 剩下的那 1 个也是假阳性（核实过）

`pixRankBinByStrip:3065→3064`：`LEPT_FREE(array)` 在 **3065**（外层 `for` 体末尾），
3064 的使用在**内层** `for` 里；下一轮**外层**循环 3061 行
`pixGetRankColorArray(..., &array, ...)` **重新赋值** `array` —— 不是 UAF。

**为什么没挡住**：回边是**内层**循环的，重新赋值发生在**外层**循环头，窄范围覆盖不到。
**要彻底解决需要真正的路径敏感分析（跨嵌套循环）** —— 那正是 R12/R14 列为"不做"的那一类。

**→ 所以 leptonica 现在的 1 个站点是假阳性撑起来的，仍然是 0 个真站点。**
