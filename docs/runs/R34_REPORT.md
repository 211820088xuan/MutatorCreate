## 步骤 1 · 去掉结构门禁后的多策略生成

### 改了哪一道

只去掉 **"结构合法性"** 那一道（`_has_structure(blob, _ab)` 对
`0/SECTION + 2/<anchor> + ≥1 条 code-0 记录` 的要求），位置在 `s5_5_build.py` 门禁 5 里。
`_has_structure` / `_record_after` 的函数体**保留**（备用），只是不再拿它判死算子。

**保留的四道**：default 权重 / 有效变异空间 / preserve(`group_code_digits`) / 构造路径(剥段 ≥400 次改动)。

### 剩下四道的结果：**被 `preserve` 挡住**

3 个 anchor（`OBJECTS` / `ENTITIES` / `ACAD_`）一次生成：

```
✗ 45/50 个采样改到了组码行，违反 preserve=group_code_digits（应只改值行）
```

生成的 `mutator.c` **没有更新**（sha1 仍是 `d7913b9e`），grep：`OBJECTS=2 / ENTITIES=0 / ACAD_=0`。

### 按你的要求：先判断这道挡得对不对 —— **它挡得对**

`preserve=group_code_digits` 验的是「**组码行不该被改，只该改值行**」。

- 对 **DXF** 来说这是**正确的不变量**：组码（`0` / `2` / `5` …）是结构骨架，改了就不是合法 DXF；
- 它**不是**"长得像不像段"那种代理指标 —— 它检查的是**每一处字节改动落在哪一行**（`DIFF` 偏移 + 行内容）；
- 三个 anchor 全都是 DXF 输入（`in_dxf.c` / `encode.c`），**这条不变量对它们都适用**。

**→ 45/50 违规说明的是「LLM 写出来的代码在改组码行」，不是「门禁提了不合理的要求」。**
**所以没有去掉它。**

### 判定：**no-op / 写不出来** —— 停下

按你的判定表第三档：「仍然 no-op → **报是哪一道门禁挡的 / 还是 LLM 写不出来**，停下」。

| 问题 | 答案 |
|---|---|
| 哪一道挡的 | **`preserve=group_code_digits`**（45/50 采样改组码行） |
| 挡得对不对 | **对**（DXF 的组码是结构骨架，不该改） |
| 是 LLM 写不出来吗 | **是** —— 3 个 anchor 时它写出的代码违反最基本的不变量 |

**这和 R31 的观察一致**：3 个 anchor 时 `default 权重 1.00` / `变异空间 0`（no-op）；
现在结构门禁去掉了，它换了个方式失败 —— **改成改组码行**。
**两次失败的方式不同，但都是"3 个 anchor 时写不出合格代码"。**

### 已恢复

`mutator.c` = `d7913b9e`，`mutation_plan.json` = 1 站点。
**本轮没有产出任何新算子。**

## 汇总

### 本轮结论一句话

**去掉结构门禁之后，3 个 anchor 的多策略生成仍然失败，但换了个原因：`preserve=group_code_digits`
（45/50 采样改组码行）。按你的要求先判断这道挡得对不对 —— 它对 DXF 是正确的不变量，
所以保留；失败的责任在 LLM 写不出合格代码。**

### 一个观察（值得记）

| 轮次 | 站点数 | 失败方式 |
|---|---|---|
| R28 | 4 | 被门禁拒（`preserve` / 格式分流） |
| R29 / R30 | 2–3 | 过门禁，但**同一算法换 salt** |
| R31 | 3 | `default 权重 1.00` / 变异空间 0 → **no-op** |
| **R34** | **3** | **`preserve` 45/50 改组码行** |

**"一次生成多个策略"这条路，四次尝试、四种失败方式。**

| # | 环节 | 状态 |
|---|---|---|
