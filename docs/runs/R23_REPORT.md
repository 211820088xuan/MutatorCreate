## 步骤 2 · 收窄守卫

### 修法

```python
_m9 = re.search(r"\b(return|break|continue|goto|exit|abort|longjmp|_Exit)\b", s)
if _m9:
    _kw = _m9.group(1)
    if _kw == "break":
        _inner = _innermost_block(_blks, j)      # `break` 所在的最内层块
        if _inner is None or _inner["kind"] != "switch":
            break                                 # 在循环里/不在块里 → 后面不可达 ✓
        # 在 switch 里：只跳出 switch，**后面的代码仍然可达** → 不终止 ✓
    else:
        break
```

**→ 按表的字面，它是"差 1 条到可用"。但按实质，它不可用。**

### 为什么不可用（三条实质理由）

**① 正例判对率 11%** —— 它**认不出真 UAF**。
用它做判定，会把 9 条真站点里的 8 条**判掉** ✗ —— **和现在的 "0 个站点" 没有区别**，
甚至更糟（现在至少知道是"扫不出"，那时会以为"扫出来了但被判假"）。

**② 同一个 prompt，两个相反的稳定答案** —— `temperature=0.0` 也复现 ✓。
**它的答案不是输入的函数。** 这比"判错"严重：判错至少有规律，这个没有。

**③ 它的能力是"证伪"而不是"证实"** ——
负例 5/5 全对（那些的假阳性理由都很**短**：`exit`、`if/else`、`next-iteration reassign`），
正例却要追**跨函数的赋值/传参链**（几条到十几跳）→ 它追不动，就判 `false_positive`。

**→ 结论：`不可用`。** 写进限制，**这条路也封掉**。

### 为什么不用"调 prompt 重跑"

用户规定："不要为了让指标好看而调 prompt 重跑。"
**而且这里的失败不是 prompt 措辞问题** —— 同一个逐字相同的 prompt 给了两个相反答案，
调措辞解决不了"答案不是输入的函数"这件事 ✓。
