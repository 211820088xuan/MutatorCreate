# 崩溃通用特征库

> 从 378 条已复现崩溃（16 项目）中提炼的通用特征。
> 每条特征 = **数据流形状 + 缺失校验 + 变异策略**，可在新项目上实例化。

## 一、特征总览

| # | 特征 | 崩溃类型 | 证据强度 |
|---|---|---|---|
| 1 | **长度字段失控** | heap/stack/global-buffer-overflow | ✅ AST 验证 + mutator 走通 |
| 2 | **未初始化读** | use-of-uninitialized-value | ⚠ 统计签名 + 数据流形状 |
| 3 | **栈缓冲越界** | stack-buffer-overflow | ⚠ 统计签名 + 代表崩溃 |
| 4 | **双重释放** | heap-double-free | ⚠ 统计签名 + 代表崩溃 |

## 特征 1：长度字段失控

**数据流形状**
```
输入字段 L  ──(算术: × 或直接)──>  内存操作.size
```

**缺失校验**
```
不存在 "size ≤ 目标缓冲区容量" 的检查
```

**变异策略**
1. 打触发门：把类型选择字段设到目标 codec；
2. 注入大值：把 L 设为超过容量的值；
3. 保持结构合法（如 `cbytes == size`）。

**项目实例**
| 项目 | 字段 L | 内存操作 | 子型 |
|---|---|---|---|
| c-blosc2 | blockshape[0], blockshape[1] | `memset(op,0,L[0]*L[1])` | 乘法 |
| libavc | `num_cols`(=wd) | `memcpy(dst,src,num_cols)` | 单字段 |
| libavc | `wd` | `memcpy(src-row*strd,src,wd)` | 单字段 |

**证据**
- `m9b_feature.py` 在 3 个崩溃点（2 项目）判 `length_overflow=true`；
- 定向 ndlz mutator 第 1 次变异即崩（default 需 3.36 亿次）。

## 特征 2：未初始化读

**数据流形状**
```
缓冲区 B  ──(读取 R)──>  未在 R 之前被写入的位置
```

**缺失校验**
```
不存在 "B 已全部初始化" 的保证/检查
```

**变异策略**
1. 缩短写入循环（少写一段）；
2. 分配缓冲区不置零；
3. 让读取覆盖未写区域（读取长度 > 写入长度）。

**项目实例**
| 项目 | 崩溃点 | 表现 |
|---|---|---|
| libhevc | `ihevc_deblk_luma_vert_ssse3:207` | 读未初始化的 SIMD 参数 `*a4/*a5` |
| libhevc | `ihevcd_iquant_itrans_recon_ctb:1049` | 写未初始化的 `sto_res_tmp2` |
| c-blosc2 | `initialize_context_decompression:1480` | `assert(jobSizeMB>=1)` 用了未初始化值 |
| hunspell | `SfxEntry::test_condition:560` | `*st == *p` 读未初始化字符 |

**签名**
- 参数可达率 **30%**（显著低于其他类型的 70%）→ 值不来自参数，来自未初始化内存；
- WRITE 率 **0%** → 是读操作。

## 特征 3：栈缓冲越界

**数据流形状**
```
输入驱动的 长度/索引 L  ──>  写入 栈上固定缓冲区 B
```

**缺失校验**
```
不存在 "L ≤ sizeof(B)" 的检查
```

**变异策略**
1. 放大索引/长度（让写越过栈缓冲）；
2. 让写入落在"预期的最大下标 + 1"处（off-by-one 型）。

**项目实例**
| 项目 | 崩溃点 | 表现 |
|---|---|---|
| espeak-ng | `Lookup:2886` | `memcpy(word, word1, len)`（word 栈缓冲） |
| hunspell | `suffix_check:2797` | `word[start+len-1]` 读越界 |
| jq | `decNumberCopy:3375` | 栈 buffer 拷贝循环越界 |
| pcre2 | `_pcre2_compile_class_not_nested_16:1638` | `ptr = hptr + 1` 越界 |

**签名**
- guard率 **20%**（显著低）→ 栈保护/边界守卫多，需更精确地绕过。

---

## 特征 4：双重释放

**数据流形状**
```
指针 P  ──(free P)──>  ──(再次 free P)──>  同一路径或不同路径
```

**缺失校验**
```
free 后没有置空 P，或没有状态检查防止重复释放
```

**变异策略**
1. 触发两次 free 路径（如错误清理路径 + 正常析构路径）；
2. 让同一指针被两个释放循环各释放一次。

**项目实例**
| 项目 | 崩溃点 | 表现 |
|---|---|---|
| hunspell | `HashMgr::~HashMgr():131/133` | 析构时同一批 `conds` 指针被释放两次 |

**签名**
- 参数可达率 **100%**、guard率 **100%**、**不在循环** → free 是直接调用，路径最短。

## 二、方法论小结

```
崩溃  →  缺陷类型归类  →  数据流形状 + 缺失校验  →  变异策略  →  mutator
```

- **通用的是**：数据流形状、缺失校验、变异策略（特征 1-4 的抽象层）；
- **项目特定的是**：具体字段偏移（如 blockshape 在 byte 28-30）。
- **实例化方法**：静态数据流（Joern CPG）+ 字节敏感性扫描（定位字段）。
